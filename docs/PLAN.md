# 作り替えの計画（2026-11-27 決定）

## 目的

- claude.ai の Artifact として動いている学習ハブを、**スマホで使える PWA** にして GitHub Pages で配る。
- 教材はアプリに入れず、各自の Claude が作った「章のデータファイル」を取り込む汎用の道具にする。
- あわせて、ユーザーの Web 開発の勉強とポートフォリオにする。

## 全体の形

```
各自の Claude（生成プロンプトを入れた claude.ai のプロジェクト）
   論文PDF ＋「II-A をお願い」
        ↓ 章のデータファイル（1行1項目の .txt。書式は docs/prompt-v7.md の 5節）
スマホのアプリ（GitHub Pages の PWA）
   「教材を追加」でファイルを選ぶ / 貼り付ける
        ↓ アプリの中で組み立て・点検（build_unit.py / check_hub_data.py を JS に移したもの）
   IndexedDB に保存
   今日 / 復習 / 単語帳 / 読む / 書く（今のハブと同じ）
```

## 段階

各段階の終わりに: テストを通す → GitHub Pages に公開 → ユーザーがスマホで確かめる → しくみを数行で説明。

| 段階 | 内容 | 終わりの目安 |
|---|---|---|
| 0. 準備 | リポジトリ作成、引き継ぎ一式（このリポジトリの最初のコミット） | 済み |
| 1. 端末で動かす | `window.claude.use` と同じ使い方の部品（db / user / sample）を IndexedDB で作り、ハブに差し込む。`tests/harness.js` の `makeDb` が手本。部品そのもののテストも足す。GitHub Actions でテスト → Pages に公開 | 公開版がスマホで開き、空の状態で動く。記録が再読み込み後も残る |
| 2. 教材の取り込み | 「教材を追加」画面: ファイル選択と貼り付け、組み立て（`build_unit.py` を JS に）、点検（`check_hub_data.py` を JS に。誤りがあれば取り込まず、場所と直し方を示す）、一覧・削除・差し替え（同じ章 ID は差し替え。記録は語と表現の文字列で引き継がれる）。新しい資料の全体図（overview）も取り込めるようにする | 生成プロンプトの書式の .txt を取り込んで、読む・復習に出る |
| 3. 書くタブ（済み） | `sample` を「依頼文をコピー → 返事を貼り戻す」に。返事の JSON が崩れていたら分かりやすく知らせる。いまの添削結果の形（`res`、`correctedJa`）はそのまま | スマホで添削の往復ができる |
| 4. PWA にする（済み） | manifest・アイコン・Service Worker（オフライン起動）、`navigator.storage.persist()`、記録と教材のバックアップの書き出し・読み込み、ホーム画面への追加の案内 | ホーム画面から起動、機内モードでも開ける、バックアップで復元できる |
| 5. 2台の記録を合わせる（作業中） | バックアップを読み込むとき、上書きでなく合わせる（カードは最後に学習した日の新しい方、学習時間は端末ごとの記録を合わせる）。`hub/merge.js`、合わせ方の決まりは `docs/backup-format.md` | パソコンとスマホを両方使える |
| 6. 移行 | いまの claude.ai のハブにある教材と記録を、段階4のバックアップの形で書き出し、スマホで読み込む。**書き出しは claude.ai の「論文リーダー」プロジェクトで行う**（ハブのデータベースと `data/users/me` は claude.ai の Artifact の道具でしか読めない）。Claude Code は書き出しの形と、変換スクリプトを用意する | ユーザーが決めた切り替え日から新しいアプリだけを使う |
| 7. 仕上げ | ポートフォリオ向けの README（画面写真・しくみ・使った技術）、他の人向けの生成プロンプト（`prompts/`。プロンプト v7 の 6節「学習ハブへの登録」を「.txt を渡してアプリで取り込む」に変えたもの）、使い方。余力があれば TypeScript ＋ Vite で作り直す | 人に見せられる状態 |

## 決まっていること・注意

- 教材・章ファイル・バックアップはリポジトリに入れない（著作物と個人の記録）。
- 端末保存はブラウザのデータを消すと消える。ホーム画面に追加して使うこと、定期的なバックアップを案内する。
- いまの claude.ai のハブは触らずに残す。移行は写すだけ。切り替え日より後に古いハブで学習した分は移らない。
- 移行が済むまで、ユーザーは今のハブを普段どおり使う。新しい章も今までどおり claude.ai で作ってよい（移行のときにまとめて移る）。
- 訳の質は生成する Claude のモデルとプロンプトで決まる。アプリの点検は形の誤りだけを見つける（意味の誤りは見つけない）。README で上位のモデルを使うよう案内する。
- ユーザーの GitHub ユーザー名は自動で付いた名前（`nd33fe66b166265-droid`）。公開の URL に出るので、ポートフォリオにするなら公開前に変えるか相談する（GitHub はユーザー名を変更できる）。
