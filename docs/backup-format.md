# バックアップの形（段階4）

アプリの「保存」→「バックアップを書き出す」で作る 1 つの JSON ファイル（`paper-reader-hub-YYYY-MM-DD.hubbackup.json`）。
**個人の記録と教材が入るので、リポジトリには入れない**（`.gitignore` 済み）。

```json
{
  "format": "paper-reader-hub-backup",
  "version": 1,
  "app": "abc1234",
  "exportedAt": "2026-11-27T10:00:00.000Z",
  "docs": [
    { "col": "sources",       "id": "xu2019",      "data": { "...": "..." } },
    { "col": "units",         "id": "xu2019-2a",   "data": { "...": "..." } },
    { "col": "texts",         "id": "xu2019-2a",   "data": { "...": "..." } },
    { "col": "overviews",     "id": "xu2019",      "data": { "...": "..." } },
    { "col": "data/users/me", "id": "srs-0",       "data": { "cards": { "...": "..." } } }
  ]
}
```

- `docs` は端末のデータベース（`hub/local-db.js`）の中身そのもの。1件 = `{ col, id, data }`。`data` の形は `docs/hub-README.md` の 5節と同じ。
- 使える `col` は `sources` `units` `texts` `overviews` と `data/users/<利用者>`。`data/users/<だれか>` は読み込むときに `data/users/me` に読み替える
  （段階6で claude.ai のハブから移すときは、そちらの利用者 ID のまま書き出してよい。ただし 1 人分だけ）。
- 読み込みの点検は `hub/pwa.js` の `parseBackup`（形・知らない入れ物・重複・`__proto__` という項目名を断る）。
- 読み込むときは「合わせる」（段階5、おすすめ）か「置き換える」を選ぶ。どちらも、前の中身は端末の別のデータベース `paper-reader-hub-undo` に取っておき、「戻す前の状態に戻す」で戻せる。
- `version` を上げるときは、古い版を読めるようにしておくこと（学習記録を失わないため）。

## 合わせる（段階5）

パソコンとスマホの両方で使うときは、片方で書き出したファイルを、もう片方で読み込んで「合わせる」。
部品は `hub/merge.js` の `HubMerge.merge(今の中身, バックアップの中身)`（画面に依らない。`tests/t18_merge.js` が確かめる）。
どちらの入力も書き換えず、新しい中身を作る。読み込む直前に、書き込みを止めた後の今の中身でもう一度合わせ直す。

| 入れ物 | 合わせ方 |
|---|---|
| 教材（`sources` `units` `texts` `overviews`） | 片方にしか無い物は足す。両方にあれば今の端末の方（章は `units` と `texts` を組で決める）。中身が違う章の数を画面で知らせる |
| 復習カード（`srs-0`〜`7`） | カードごとに `last`（最後に学習した時刻）が新しい方。片方にしか無いカードは足す |
| `meta` | 設定は今の端末のまま。今日の数（`newDone` `reviewsDone` `phrDone` `fixAdded` `revDone`）は同じ `day` なら大きい方、違えば新しい日の方。`lastReview` `skipThrough` `capDay` `pauseDay` は新しい方。`shiftNote` は今の端末の分（`fixed: true` を付ける） |
| `time-` | 日ごと・端末 ID ごとに足し合わせる。同じ端末の同じ日が両方にあれば項目ごとに大きい方 |
| `log-` | 1件ずつ足す。両方にあれば消した方（`del`）、次に `at` が新しい方 |
| `sum-` | 1件ずつ足す。両方にあれば `at` / `rewriteAt` の新しい方。`res.correctedJa` が片方だけなら足す |
| `fixes` | 1枚ずつ足す。両方にあれば今の端末の方 |
| `progress` | 章ごとに `at` が新しい方。`max` は大きい方 |
| `archive` | 資料ごとに `at` が新しい方 |
| そのほか | 片方だけなら足す。両方にあれば今の端末の方 |

**「復習しなかった日」のずらし過ぎを戻す**: ハブは開いたときに、前に復習した日の翌日から昨日までを「復習しなかった日」として、
復習中のカードの期日をまとめて後ろへずらす（`applySkippedDays`。範囲は `meta.shiftNote = {from, to, n, day}`）。
2台で使うと、片方ではずらした日に、もう片方で復習していることがある。合わせるとき、その端末の `shiftNote` の範囲のうち
「もう片方で復習した日」（学習時間の `review` がある日・カードの `last` の日・`lastReview`）の数だけ、ずらした日より前に学習したカードの期日を戻す。
同じ時刻に学習した同じカードが両方にあれば、戻した後の遅い方の期日にする（本当にどちらでも復習しなかった日のずれは残る）。
合わせた後は `shiftNote.fixed = true` にして、次に合わせるとき二重に戻さない。

**分かっている限り**: 片方で消した物（「未学習に戻す」をしたカード、教材の章）は、もう片方に残っていれば合わせると戻ってくる。
手入力の記録は消した印（`del`）を残すので戻らない。
